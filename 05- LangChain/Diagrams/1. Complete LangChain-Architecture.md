# LangChain Architecture — Diagram

## 1. High-Level LangChain Architecture

```text
                           USER
                            │
                            ▼
                         Query
                            │
                            ▼
                 ┌─────────────────────┐
                 │   LangChain Layer   │
                 └─────────────────────┘
                            │
          ┌─────────────────┼─────────────────┐
          │                 │                 │
          ▼                 ▼                 ▼
       Prompts          Retrievers          Tools
          │                 │                 │
          │                 │                 │
          ▼                 ▼                 ▼
      Chat Model       Vector Store      External APIs
          │                 │             Databases
          │                 │             Services
          └─────────────────┼─────────────────┘
                            │
                            ▼
                       Application
                         Response
```

LangChain sits between application logic and different LLM-related capabilities.

It provides abstractions for connecting:

```text
Prompts
Models
Documents
Retrievers
Vector Stores
Tools
Output Handling
External Systems
```

- Original user question

## 5. Manual RAG vs LangChain Architecture

### Manual RAG

```text
User Question
     │
     ▼
Custom Retriever
     │
     ▼
Custom Context Builder
     │
     ▼
Custom Prompt Builder
     │
     ▼
Custom LLM Service
     │
     ▼
Custom Response Handling
     │
     ▼
Answer
```

### LangChain

```text
User Question
     │
     ▼
Retriever
     │
     ▼
RunnableLambda
     │
     ▼
ChatPromptTemplate
     │
     ▼
Chat Model
     │
     ▼
Output Parser
     │
     ▼
Answer
```

LangChain does not change the underlying architecture.

It standardizes many components.

## 10. Production Boundary

LangChain should operate inside application security boundaries.

Correct:

```text
                    Authenticated User
                           │
                           ▼
                     Authorization
                           │
                           ▼
                   Allowed Data Scope
                           │
                           ▼
                       Retriever
                           │
                           ▼
                 Authorized Documents
                           │
                           ▼
                       LangChain
                           │
                           ▼
                          LLM
```

Incorrect:

```text
Retrieve Everything
        │
        ▼
       LLM
        │
        ▼
"Decide what user is allowed to see"
```

Authorization must remain deterministic application logic.

## Final Architecture Takeaway

LangChain can be viewed as a framework that standardizes and connects:

```text
Data
+
Retrieval
+
Prompts
+
Models
+
Output Handling
+
Tools
```

The framework helps with composition and execution.

The underlying architecture, security, retrieval quality, business rules, and evaluation still remain the responsibility of the application.
